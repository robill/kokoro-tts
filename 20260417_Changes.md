# Changes — 17 April 2026

## Overview

Added a full multi-speaker audio generation pipeline on top of the existing
`kokoro_tts` engine.  Two new entry-point scripts and two convenience batch
files were created; the existing codebase was not modified.

---

## New Files

### `podcast_tts.py`
Core generation script.  Handles both **podcast** and **interview Q&A**
markdown formats, strips markdown markup, expands abbreviations, and produces
a single MP3 (or WAV) from a multi-speaker script.

Key capabilities:

| Feature | Detail |
|---|---|
| Multi-speaker support | Arbitrary number of speakers; each mapped to a kokoro voice or voice blend |
| Voice blending | Passes blend specs (`af_nicole:70,bm_lewis:30`) directly to `validate_voice` |
| **Both** speaker | Renders the line with each of the two main host voices independently, then overlays and peak-normalises the two tracks |
| Markdown stripping | Removes `**bold**`, `*italic*`, headings, list bullets, blockquotes, code, etc. before TTS |
| Abbreviation expansion | Loads a JSON map; applies longest-match substitution; falls back to auto-spacing any remaining ALL-CAPS word |
| Silence padding | Configurable gap (ms) inserted between every speaker turn |
| GPU acceleration | Respects `ONNX_PROVIDER=CUDAExecutionProvider` set in the environment |
| Auto format | Writes WAV via `soundfile`; converts to MP3 via `pydub` + ffmpeg |
| `--list-speakers` | Preview detected speakers and voice assignments without generating audio |
| `--dry-run` | Print all segments (with markdown stripped and abbreviations expanded) without generating audio |

#### Script-type support

| Flag | Format | Speakers produced |
|---|---|---|
| `--script-type podcast` | `**Host A:** text` | As written in the script |
| `--script-type qa` | `### Q1: text` / `**Model Answer:**` / `**Follow-up Probe:**` | `Interviewer` / `Candidate` |
| `--script-type auto` *(default)* | Detects by scanning for `**Model Answer:**` / `**Follow-up Probe:**` | — |

For the **Q&A** parser:
- `### Q<n>: text` → `Interviewer`, spoken as `"Question N. text"`
- `**Model Answer:** text` → `Candidate`
- `**Follow-up Probe:** text` → `Interviewer`, spoken as `"Follow-up question. text"`
- `## Quick Reference` section is skipped entirely (it is a repetition of the questions)

#### CLI reference

```
python podcast_tts.py <script.md> [output.mp3] [options]

  --voice-map MAP        e.g. "Host A=af_nicole:70,bm_lewis:30,Host B=bm_lewis"
  --default-voice VOICE  Fallback for unmapped speakers (default: af_heart)
  --lang CODE            Language code (default: en-us)
  --speed FLOAT          Speech speed (default: 1.0)
  --silence MS           Silence between turns in ms (default: 400)
  --format {wav,mp3}     Output format (default: mp3)
  --abbr-map FILE        Abbreviation map JSON (default: abbreviations.json)
  --script-type          auto | podcast | qa (default: auto)
  --list-speakers        Print speaker/voice mapping and exit
  --dry-run              Print segments without generating audio
  --model PATH           Path to kokoro-v1.0.onnx
  --voices-bin PATH      Path to voices-v1.0.bin
  --debug                Verbose TTS debug output
```

### `abbreviations.json`
Standalone JSON configuration file for abbreviation-to-spoken-form mappings.
Loaded at runtime; no script edit required to add or change entries.

**Format** — entries can be flat or grouped into named sections:
```json
{
    "Section name": {
        "ABBR":   "spoken form",
        "ASIL-B": "AY-sil B"
    }
}
```
Keys starting with `_` are treated as comments and ignored.  Entries are
matched **longest-first** so `ASIL-B` is substituted before `ASIL`.

**Fallback** — any remaining 3–6 character ALL-CAPS word not in the map is
automatically letter-spaced (`ABC` → `A B C`).

Initial entries (31 total) cover:

| Group | Examples |
|---|---|
| Project / product | `AQRP`, `ICAST`, `SWPF`, `HOSP`, `PL1`, `HDK` |
| Safety | `ASIL-B/A/C/D` → `AY-sil …`, `ASIL` → `AY-sil` |
| Automotive / embedded | `AUTOSAR` → `Auto Sar`, `QNX` → `Q N X`, `SoC` → `System on Chip`, `S32G` → `S 32 G` |
| Teams / processes | `ANS`, `ACM`, `IEP`, `HEP`, `PMT`, `DevOps` |
| Roles / ceremonies | `STE`, `RTE` |
| Milestones / planning | `SOP`, `TSO`, `CI/CT` → `C I, C T` |
| Architecture levels | `L1/L2/L3` → `Level 1/2/3` |

### `run_podcast.bat`
Convenience launcher for podcast-format scripts.

```bat
run_podcast.bat <script.md> [output.mp3]
```

Configured defaults:
- `ONNX_PROVIDER=CUDAExecutionProvider` (GPU)
- `Host A` → `af_sarah` (US female)
- `Host B` → `bm_lewis` (British male)
- `Both` → `af_heart` (default fallback, plays as single voice)
- `--silence 500` ms
- `--abbr-map abbreviations.json`

---

### `run_qa.bat`
Convenience launcher for interview Q&A-format scripts.

```bat
run_qa.bat <qa_script.md> [output.mp3]
```

Configured defaults:
- `ONNX_PROVIDER=CUDAExecutionProvider` (GPU)
- `Interviewer` → `bm_lewis` (British male)
- `Candidate` → `af_sarah` (US female)
- `--silence 600` ms (longer gap to let answers breathe)
- `--script-type qa` (explicit; bypasses auto-detection)
- `--abbr-map abbreviations.json`

## Implementation Notes

### Markdown stripping (`_strip_markdown`)
Applied to every segment before it reaches the TTS engine.  Patterns (in
order): headings, links/images, fenced/inline code, bold+italic, bold,
italic (`*` and `_`), strikethrough, list bullets, ordered list numbers,
blockquotes, horizontal rules, whitespace collapse.

### Abbreviation expansion (`_expand_abbreviations`)
1. Apply all entries from `abbreviations.json` longest-first.
2. Regex boundary `(?<![\w-])ABBR(?![\w-])` prevents partial matches inside
   hyphenated or compound words.
3. Fallback `_CAPS_RE` spaces out any surviving 3–6 char ALL-CAPS token.

### `Both` speaker mixing (`_mix_audio`)
- Two audio arrays are generated independently (one per main host voice).
- Arrays are zero-padded to equal length, summed, then peak-normalised
  (`/ max(abs(mixed))`) to prevent clipping.

### Voice-map parsing (`_parse_voice_map`)
Splits on `,(?=[^=,]+=)` so that blend specs containing commas
(`af_nicole:70,bm_lewis:30`) are not incorrectly split.

### GPU enablement
`ONNX_PROVIDER=CUDAExecutionProvider` is set in both batch files before
invoking Python, matching the approach in the pre-existing `enable_GPU.bat`.
The `kokoro_onnx` library picks this up via `os.getenv("ONNX_PROVIDER")`.
