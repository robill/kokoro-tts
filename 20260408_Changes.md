# Changes — 2026-04-08

## 1. Ordered/unordered list enumeration in TTS output (`kokoro_tts/__init__.py`)

**Problem:** `BeautifulSoup.get_text()` discards list numbering because `<ol>`/`<li>` markers are CSS-rendered, not text nodes.

**Fix:** Added `soup_to_text()` helper that walks the DOM and prefixes:
- `<ol>` items with `1.`, `2.`, … (respects `type="a"`, `type="A"`, and `start=` attributes for nested lists)
- `<ul>` items with `- `

Replaced all TTS content-extraction `get_text()` calls with `soup_to_text()`:
- `extract_text_from_epub()`
- `get_chapter_content()` (fragment extraction)
- Two fallback paths in `process_toc_items()`

---

## 2. Block-level pause separation (`soup_to_text`)

**Problem:** Block elements (`<h1>`–`<h6>`, `<p>`, `<div>`, etc.) were concatenated without separation, so TTS produced no pause between sections.

**Fix:** Inside `soup_to_text()`:
- Block-level tags are wrapped with `\n…\n`.
- `_ensure_sentence_end()` appends a `.` to any block/list-item text not already ending with `.!?:;`.
- `<br>` emits `\n`.
- `<head>` is skipped entirely (title/metadata excluded from TTS).
- Non-text `NavigableString` subtypes (processing instructions, doctypes, comments) are excluded via exact `type()` check.
- Raw text node newlines (HTML soft-wrap) are collapsed to a single space via `re.sub(r'\s+', ' ', ...)`.

---

## 3. Newline→sentence-boundary in `chunk_text()` (`kokoro_tts/__init__.py`)

**Problem:** `chunk_text()` called `text.replace('\n', ' ')`, which erased the block-boundary newlines injected by `soup_to_text()`, losing all pauses before chunking.

**Fix:** Replaced the replacement with:
```python
normalised = re.sub(r'\n+', '. ', text)           # newline → sentence break
normalised = re.sub(r'\.(\s*\.)+', '.', normalised)  # deduplicate consecutive periods
```

---

## 4. Per-chunk text dump files (`kokoro_tts/__init__.py`)

Added `write_chunk_dump()` inside `convert_text_to_audio()` that writes each chunk's text to a file for inspection:

- File naming: `<input_basename>_ch<NNN>_chunk_<NNNN>.txt`  
  e.g. `aab-dk_test1_ch001_chunk_0001.txt`
- Files are only written when `--dry-run` is active (not during normal audio generation).

---

## 5. `--dry-run` flag (`kokoro_tts/__init__.py`)

**Added** a new `--dry-run` CLI flag that:
- Skips model file checks and Kokoro model loading entirely.
- Skips all TTS generation (`process_chunk_sequential` calls).
- Still extracts chapters, chunks text, and writes chunk dump files.
- Registered in `get_valid_options()` and wired through `main()` → `convert_text_to_audio()`.

Usage:
```
python -m kokoro_tts aab-dk_test1.epub "out.mp3" --lang en-us --voice "af_nicole:70,bm_lewis:30" --format mp3 --dry-run
```

---

## 6. Word count report during `--dry-run` (`kokoro_tts/__init__.py`)

During `--dry-run`, each chunk now prints a summary line after the spinner stops:

```
  chunk  1/4    187 words  'Alice Bailey & Djwhal Khul - Esoteric Psychology II...'
  chunk  2/4    162 words  '1. A great many men, and the number is rapidly incre...'
```

A grand total is printed after all chapters are processed:

```
Total: 4 chunks, 644 words
```

Implemented via a `dry_run_total_words` accumulator alongside the existing `chunk_dump_counter`.

---

## 7. Remove chunk-text stdout debug output (`process_chunk_sequential`)

Removed the `DEBUG: --- chunk text begin --- … chunk text end ---` block that previously printed each chunk's full text to stdout under `--debug`, since chunk dumps are now written to files instead.
